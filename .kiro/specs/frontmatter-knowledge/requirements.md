# 要求定義: フロントマターの閲覧・検索強化

対象Issue: #62 / #63 / #24。3件を単一のspec・実装・PRで扱う。

## スコープ

- [x] sourcesの文書相対リンク・外部URLの一覧と、出典としての利用先の逆引き
- [x] 本文上部の選択属性表示、ネストした属性の構造表示、表示キー・ラベル・状態表示名の設定
- [x] Source内の属性・タグ・フォルダー範囲・URLによる検索と結果への遷移
- [x] NativeSource / ZipSource、更新・明示更新・解析失敗・部分結果の表示
- [x] 有限なYAML解析と読込、既存の信頼境界、元ファイル非変更

## 振る舞い

- sourcesは文字列配列。文書リンクと外部HTTP(S) URLを区別し、外部通信は明示操作時だけ行う。
- ローカル出典は保有文書を基準に解決し、欠落・範囲外・未対応・検証不能を区別する。
- 出典関係と本文の一般リンクは別の一覧。既存グラフの意味を変更しない。
- 表示属性は順序付きで設定でき、値やラベルの表示名も設定できる。未知の属性は詳細から確認できる。
- 確認状態・記録日・確認日・分類・登録時の文脈に自動的な意味の補完や書き換えを行わない。
- 検索条件はAND。キーの有無、値の完全一致・部分一致、文字列配列の要素一致を扱う。
- 検索結果はtitle→先頭H1→ファイル名のタイトル、パス、description、選択属性を表示する。
- 索引は必要時に作り、Source世代・表示設定・watcher更新を反映する。古い応答で新しい状態を上書きしない。
- 上限・読込失敗・YAML解析失敗を空結果と区別し、部分結果として表示する。

## 対象外

編集、自動分類、確認フロー管理、本文ハッシュタグの統合、タグの階層管理、意味検索、外部カタログ依存、PDF/HTMLの表示エンジン追加。
