# 要求定義: Markdown文書の分割ビュー

対象: [Issue #25](https://github.com/cocoabreak/hiranoa/issues/25)

ステータス: 実装・検証完了。

## 目的と初期スコープ

整理した知識と出典、二つの文書、同じ文書の別の位置、Markdownソースとレンダリング結果を並べて読む。

- 左右の最大2ペイン。各ペインがタブ一覧とアクティブタブを持つ。
- 文書ごとの表示モード・位置、ペインごとの検索・ナビゲーション履歴を独立させる。
- 通常操作は操作中のペインに適用し、「反対側で開く」を明示的に選べる。
- 比率・タブ構成・表示状態を既存のセッション復元へ統合する。
- NativeSourceとZipSource、および両者を左右に並べる場合を扱う。

## US-001: 分割・解除とタブ操作

- [x] 文書を開いているとき、「右側に分割」で現在の文書を右ペインへ複製できる。最初は50:50、右側を操作対象にする。
- [x] 複製時は表示モードと現在位置を引き継ぐ。新しいペインの検索は空、履歴は表示中の文書1件から始める。
- [x] 分割中は3つ目のペインを作成せず、各ペインでタブ切替・ピン留め・並べ替え・一括クローズを使える。
- [x] 同じ文書は左右に1つずつ開ける。同一ペイン内の同じ文書は既存タブを選択する。
- [x] 分割中はタブの「反対側へ移動」「反対側で開く」を使える。移動先に同じ文書がある場合は統合し、ピン留めはどちらかが有効なら保持する。
- [x] 「分割を解除」は操作中のペインを残し、他方の異なる文書のタブを合流する。同じ文書は残す側の表示モード・位置を優先し、ピン留めを保持する。
- [x] 他方にだけあるタブの順序を保って合流し、既存のピン留めグループ規則を適用する。
- [x] 片側の最後のタブを閉じると残る側を全幅に戻す。最後のピン留めタブは既存規則どおり通常のクローズで閉じない。
- [x] 閉じたタブは既存の最大10件の履歴で扱い、元ペインが残っていればそこへ、なければ操作中のペインへ復元する。

## US-002: 独立した閲覧と操作対象

- [x] 左右で別文書、同じ文書の別位置、ソース／レンダリングを同時に表示できる。
- [x] スクロール位置と表示モードは各タブ表示で独立する。検索語・正規表現設定・検索結果と、戻る／進むはペインごとに独立する。
- [x] クリック、タブ選択、キーボードフォーカスで操作中のペインを切り替え、枠・タブバー等で対象が分かる。
- [x] ホバー、ホイールだけのスクロール、再描画、バックグラウンド更新で操作対象を変更しない。
- [x] 左右のどちらでも、アンカー、目次、検索ハイライト、脚注、図、コピーが他方へ誤適用されない。
- [x] 既存のID指定を含むカスタムCSSが、通常表示・同一文書の左右表示・対象文書の印刷で適用される。
- [x] Ctrl+F、タブ切替・クローズ、ソース表示、外部エディター、参照コピー等の既存コマンドは操作中のペインへ適用する。
- [x] 左右へのフォーカス移動と分割・解除をコマンドパレットから実行できる。既定キーはdesign.mdに記載する。

## US-003: リンクと共有パネル

- [x] 左のExplorer・全文／属性検索と、右の目次・メタデータ・出典、リンクインスペクター、リンクグラフ、下部ステータスバーは共有し、操作中のペインに追従する。
- [x] Explorerのルートはアプリ全体で一つとし、各ペインの文書のSourceとは区別する。
- [x] 本文・出典・リンク一覧から通常どおり開くと操作元または操作中のペインで開く。
- [x] 対応するローカルMarkdownリンクに「反対側で開く」を追加する。未分割なら読み込み・確認成功後に右側を作り、開いた側へフォーカスする。
- [x] 元のペインの閲覧位置・表示文書・ナビゲーション履歴は「反対側で開く」で変化しない。
- [x] 開き先に同じ文書があれば既存タブを選択し、通常は位置を維持する。見出し指定がある場合は開き先だけを移動する。
- [x] 外部Web URLは既存の外部ブラウザー経路で開く。
- [x] 非同期読込開始時の対象ペインを保持する。完了待ちの間のフォーカス変更やペイン削除で別のペインへ結果を適用しない。
- [x] 印刷・PDF・HTML出力は操作対象の文書だけを扱う。右クリックメニューは右クリックしたペインの文書を対象にする。

## US-004: 更新・資源の寿命

- [x] 同じ文書を左右で表示中、片側を閉じても残る側の本文キャッシュ・watcher・Sourceを解放しない。
- [x] 同じ文書への更新は共有した本文へ反映し、左右それぞれの位置・表示モード・検索を維持／再計算する。
- [x] 削除やZIP更新は全ペインへ通知し、一部の読込失敗で他の表示を破棄しない。
- [x] ペインを閉じると、そのペインの描画・Observer・検索Worker・イベント購読を片付ける。他方の処理は継続する。
- [x] セーフモードとリッチ表示の確認は既存の規則に従う。同じ文書の表示を複製しても確認の迂回を作らない。

## US-005: レイアウトと復元

- [x] 分割境界をポインターとキーボードで操作でき、ダブルクリックで50:50へ戻せる。
- [x] 推奨値は各ペイン最小280px、比率20〜80%。狭幅動作は下記の承認済み方針に従う。
- [x] ペインのタブ構成、各アクティブタブ、操作中のペイン、分割比率、各タブの表示モード・モード別位置、各ペインの検索条件を保存・復元する。
- [x] 現行のフラットなセッションを左の1ペインへ移行できる。過去の検索条件も左へ移す。
- [x] 再起動時の復元確認、リロード前の保存完了待ち、復元確認中の上書き防止を維持する。
- [x] 復元できない文書はスキップする。片側が空なら有効な側を1ペインで残す。
- [x] ペイン数・タブ合計・位置・比率・検索条件・保存サイズを検証し、保存情報だけで信頼済みルートを増やさない。

## 非機能要求

- 読み取り専用の方針、DocumentSource、AllowedRoots、サニタイズ、CSPを維持する。
- 新たなWebView・iframe・汎用レイアウトライブラリは追加しない。
- 未分割時は2つ目のビューワーを生成しない。Shiki・KaTeX・Mermaid等の重い初期化は共有する。
- 既存の初期ロード・総配布サイズの予算を維持し、`npm run perf:ci`で検証する。
- Native/ZIP、同一文書、遅い描画・読込、片側の閉じ操作、復元の境界をテストする。

## 後続候補

上下分割、3ペイン以上、同期スクロール、差分比較、ペインをまたぐタブのドラッグ、ペインごとのExplorerルート、ズーム・テーマ・レンダラー設定の独立、名前付きレイアウト保存（#28）、左右まとめての印刷。

## 承認済みの方針

1. 共有の右パネルを操作中のペインへ追従させる。
2. 分割解除時はタブを合流し、同じ文書は操作中側の閲覧状態を優先する。重複した別表示の位置は保存し続けない。
3. 狭い場合はまず共有目次をドロワー化する。それでも中央に2ペイン分の幅がなければ、構成を保持したまま操作中側だけを一時表示し、左右の切替操作を提供する。幅を戻すと並列表示へ戻す。
4. 検索条件は各ペイン単位、ナビゲーション履歴は実行中のみ。全体テーマ・ズームは共有する。
