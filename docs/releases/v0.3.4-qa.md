# Hiranoa 0.3.4 QA

## Scope and acceptance

This release includes the frontmatter browsing, source-reference, and property-search
features from PR #64; the independent-tab split view from PR #65; and the
operating-system certificate verification and update-error diagnostics from Issue #66.
The changelog covers all changes since v0.3.3.

## Validation before publication

- Version 0.3.4 is synchronized across npm and Cargo package metadata, both lockfiles,
  and the Tauri configuration.
- Frontend formatting, ESLint, and svelte-check passed with zero diagnostics.
- All 482 frontend tests passed with coverage enabled.
- All 166 Rust tests, rustfmt, and Clippy with warnings denied passed.
- All 106 performance-tool tests passed. Production builds and frontend size limits
  passed, and production output excludes development E2E hooks.
- Twelve Windows WebView2 smoke scenarios passed, including Markdown dialects,
  math and Mermaid rendering, native and ZIP directory links, large-file safe mode,
  split-view isolation, update notification, and session restoration.
- Windows runtime checks verified successful GitHub update requests and real
  connection failures. Error details were displayed and copied verbatim; copy
  rejection, retry reset, and removal of the error panel after success were checked.
- Rust tests verify OS certificate verification remains enabled, nested diagnostic
  causes are preserved, and a timed-out worker retains its execution reservation
  until completion. Worker-panic cleanup and result caching are covered.
- npm and Cargo audits passed without vulnerabilities after updating the indirect
  webpki-root-certs dependency to 1.0.10.

## Remaining warnings and limits

The five previously documented upstream Cargo advisory warnings remain:
glib, proc-macro-error, zbus_names, zvariant, and zvariant_derive. No advisory
suppressions were added.

OS certificate verification may continue after the caller receives its five-second
timeout. Only one update request can remain active, and its completion releases
the reservation and caches the actual result.

Windows is the interactive verification platform. Linux/macOS runtime and
installer installation are not covered by local QA; their packages are gated by
release builds. Full startup/memory benchmarks and native printing were not
repeated. Windows binaries are unsigned; macOS packages are not notarized.

## Publication gates

Final independent design/diff and security reviews, PR CI, tagged Windows/macOS/Linux
builds, and verification of all distribution checksums must complete before the
draft is published. Final build and asset verification results are recorded on
the Release.
