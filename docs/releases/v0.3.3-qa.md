# Hiranoa 0.3.3 QA

## Scope and acceptance

Issues #59, #45, #36, and #46: external-editor settings persistence,
test-tool updates, KaTeX font-format reduction, and markdown-it 15 migration.
The user accepted the local Windows candidate before requesting publication.
The application architecture, native authorization boundaries, and settings schema
remain unchanged.

## Validation before version preparation

- Frontend formatting, ESLint, and svelte-check passed with zero diagnostics.
- All 430 frontend tests, coverage, and 106 performance-tool tests passed.
- Clean npm installation, frontend size limits, production builds, and production
  E2E-hook exclusion passed.
- Eleven Windows WebView2 smoke scenarios passed twice consecutively, including
  combined Markdown dialects, links, math, ZIP, and session restoration.
- Production frontend rendering verified footnotes, definition lists, Callouts,
  Wiki links, automatic links, and math without the development E2E hook.
- External-editor persistence was reproduced before the fix. Two isolated real
  application launches verified restoration and preservation on later saves.
  Tests cover authorization rejection and errors. An isolated process probe
  verified paths containing spaces, Japanese characters, and shell metacharacters.
- At the KaTeX-only stage, all 20 original WOFF2 font contents were preserved
  (19 files plus one inlined font). All faces loaded, and four formulas had
  identical text and dimensions in screen and print CSS media before and after.
  Local MSI, NSIS, portable ZIP, and executable sizes decreased; see
  [the measurements](katex-fonts-36.json).
- Windows optimized builds generated the executable, MSI, and NSIS installers.
- Independent design/diff and security reviews of each issue found no remaining
  P0-P3 findings.

## Remaining warnings and limits

The previously documented five upstream Cargo advisory warnings remain in Linux
dependency paths: glib, proc-macro-error, zbus_names, zvariant, and zvariant_derive.
No advisory suppressions or new type-checking suppressions were added.
The local deepmerge security fix remains in use.

Windows is the interactive runtime verification platform. Linux/macOS runtime
and installation are not covered; their packages are gated by release builds.
Print CSS media was checked without exercising a physical printer or native
print dialog. HTML export retains its existing behavior and does not package
KaTeX styles/fonts. Native external-editor confirmation followed by an actual
editor launch was not automated end to end. Full startup/memory benchmarks
were not repeated. Windows binaries are unsigned; macOS packages are not notarized.

## Publication gates

Version consistency, fresh npm/Cargo audits, final release preparation review,
PR CI, tagged Windows/macOS/Linux builds, and SHA256SUMS.txt verification must
complete before publishing the draft. Final results are recorded on the Release.
